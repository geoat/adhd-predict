# Enable Cloudflare previews

This project deploys the Next.js application as a Cloudflare Worker using Vinext. Cloudflare Preview Builds run the configured build command first, then Wrangler creates a preview from the generated Worker.

## What Cloudflare does by default

Wrangler provides the preview command, but it does not infer a framework's Worker entrypoint or build output directory. A configuration must declare:

- a Worker `main` entrypoint or an assets directory;
- `previews: {}` to enable `wrangler preview`.

Cloudflare Workers Builds uses the configured production branch for production deployments. Non-production branches and pull requests can receive separate previews when Preview Builds are enabled. Preview names and URLs are generated by Cloudflare.

The project-specific settings below tell Wrangler where Vinext writes the Worker and client assets.

## Repository configuration

### Wrangler

`wrangler.jsonc` must contain:

```jsonc
{
  "$schema": "node_modules/wrangler/config-schema.json",
  "name": "adhd-predict",
  "compatibility_date": "2026-09-25",
  "compatibility_flags": ["nodejs_compat"],
  "main": "vinext/server/fetch-handler",
  "assets": {
    "directory": "dist/client",
    "not_found_handling": "none",
    "binding": "ASSETS"
  },
  "previews": {}
}
```

The empty `previews` block is required by `wrangler preview`. The `main` value is Vinext's build-time entrypoint; do not replace it with a missing source file or a hand-written wrapper that imports `dist/server/index.js` before it exists.

### Next.js

Do not use static export mode:

```ts
const nextConfig: NextConfig = {};
```

`output: "export"` produces only static files and prevents Server Actions, route handlers, cookies, and other server-side behavior from running in the Worker.

### Vinext and Cloudflare Vite

`vite.config.ts` must load both Vinext and the Cloudflare Vite plugin:

```ts
import { cloudflare } from "@cloudflare/vite-plugin";
import vinext from "vinext";
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [
    vinext(),
    cloudflare({
      viteEnvironment: {
        name: "rsc",
        childEnvironments: ["ssr"],
      },
    }),
  ],
});
```

Install and lock these packages in `package.json` and `package-lock.json`:

- `vinext`
- `@vinext/cloudflare`
- `@cloudflare/vite-plugin`
- `@vitejs/plugin-rsc`
- `vite`
- `wrangler`
- `react-server-dom-webpack`

Always commit the lockfile. A corrupted or mismatched lockfile causes Cloudflare's `npm ci` step to fail before the build starts.

## Build and deploy scripts

The Cloudflare Build command should be:

```bash
npm run build
```

The `build` script must run Vinext:

```json
"build": "vinext build"
```

The generated build creates:

- `dist/server/index.js` — the Worker server;
- `dist/server/wrangler.json` — generated Wrangler configuration;
- `dist/client` — client assets.

Recommended package scripts:

```json
{
  "build:vinext": "vinext build",
  "deploy": "npm run build:vinext && wrangler deploy --config dist/server/wrangler.json",
  "preview": "npm run build:vinext && wrangler preview --config dist/server/wrangler.json"
}
```

Use the generated config for local or manual deployments:

```bash
npm run build:vinext
npx wrangler preview --config dist/server/wrangler.json
```

This avoids the error where Wrangler reads the source config and reports that `vinext/server/fetch-handler` cannot be found.

## Cloudflare dashboard settings

In Workers & Pages → your Worker → Builds:

- Production branch: `main`;
- Enable Preview Builds;
- Build command: `npm run build`;
- Production deploy command: `npx wrangler deploy --config dist/server/wrangler.json`;
- Preview command: `npx wrangler preview --config dist/server/wrangler.json`.

The explicit `--config dist/server/wrangler.json` form ensures Wrangler uses the generated Worker configuration after the Vinext build.

## Common failures and fixes

### Missing `previews` block

Add this at the top level of `wrangler.jsonc`:

```json
"previews": {}
```

### Missing entrypoint or assets directory

Wrangler needs either a Worker entrypoint or an assets directory. The final Worker configuration supplies both through Vinext and `dist/client`.

### `vinext/server/fetch-handler` not found

Run the Vinext build first and use the generated configuration:

```bash
npm run build:vinext
npx wrangler preview --config dist/server/wrangler.json
```

Do not point `main` at a non-existent `src/index.ts`, `dist/server/index.js` before the build, or a custom wrapper that imports the generated file before it exists.

### 404 at the preview root

Serving `public/` directly does not serve the Next.js application. Use Vinext's generated `dist/client` assets and Worker server instead.

### Worker Error 1101

If the Worker calls `env.ASSETS`, the assets binding must explicitly be named:

```json
"binding": "ASSETS"
```

### Build succeeds but route classification is `Unknown`

Vinext's static analysis may print this warning for dynamic APIs or Server Actions. It is non-fatal. Verify behavior by calling the action from the deployed preview.

## Verification checklist

Run locally before relying on a preview:

```bash
npm ci
npm run lint
npm run build:vinext
npx wrangler deploy --dry-run --no-bundle
```

Then deploy a preview and test the actual URL. For Server Actions, click the frontend control and confirm the response is generated by the Worker, not hard-coded client text.
